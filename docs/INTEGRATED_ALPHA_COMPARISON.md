The package retains the previously reviewed source investigation, controlled marker comparisons, browser evidence and local lab engines. It adds their missing links to planned test coverage and restart/retest views instead of rebuilding them. File windows and delegation are exercised together by one deterministic CLI fixture; scope revocation and export are exercised with native GET evidence in another.

Validation must report exact candidate binary hash and results. The existing runtime benchmark can compare this Blue Dragon build with its retained 0.8 binary on identical deterministic fixtures. It does not measure model intelligence, live browser quality, Alpha success rate, latency on a phone, or universal task parity. Alpha's source being present does not supply a validated compatible runtime adapter. Remaining platform/CI/device gaps must stay explicit until actually tested.

Follow-up source review (separate branch from frozen 51650ba): Alpha `alphacode_security_core/hypothesis_set.rs` preserves alternatives, required verification and assumptions, while `alphacode_app_core/tool/browser.rs` pins owned tabs and distinguishes readiness operations. Blue already has dedicated browser ownership, connection epochs, bounded waits and controlled-input comparison. The added research extension therefore targets missing cross-links: pinned competing existing findings, case/citation matrices, and non-causal same-request response retest deltas. It deliberately reuses browser boundaries instead of adding duplicate actions. Browser-derived test qualification, general experiment scheduling and automatic semantic refutation remain gaps; these source comparisons do not establish runtime parity.
