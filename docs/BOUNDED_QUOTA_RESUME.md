# Bounded root-turn quota recovery

Previously a typed pre-stream HTTP 429 ended the turn even with `Retry-After: 60`. The root agent now permits one wait/retry per user turn when the provider explicitly supplies a cooldown of 0..60 seconds (header or body). It waits that duration plus one second to respect the durable cross-session timestamp guard, polling cancellation every 50ms. The session is saved before waiting. The retry keeps provider/model, original user constraints and completed tool results; normal shared RPM/TPM/cooldown admission runs again. A second 429 ends recovery and cannot cascade into rotation. Partial streams, unknown transmission outcomes and HTTP400 do not enter this path.

This is not an unlimited retry policy: program-default 300s and explicit cooldowns above 60s remain visible blockers, as do extensions of shared cooldowns by another process. Child-agent/provider layers do not add retries. Ordinary context recovery and eligible non-429 fallback retain their own existing bounds. The provider error text now says `provider_layer_retries=0`, distinguishing that layer from root recovery.

Tests use actual CLI and a local HTTP provider for account/unknown/model limits, repeated rejection, HTTP400, absent/long Retry-After, and a specifically approved local counter command whose count remains exactly one through provider recovery. A normal completion-review followup after the command is counted separately, not hidden as a retry. The 60-second test observed two requests and 61.047 seconds without model change. A native agent test cancels on the cooldown notice and verifies one request, preserved user constraints and no observations. This is not a live service quota measurement or a promise of eliminating 429. Queue/phone interaction still needs real-device acceptance; saving the turn does not imply unknown tool actions may be repeated.

The queued-input CLI regression preloads a second bilingual user message while the first request is cooling down; the retry receives the first turn unchanged and the next turn retains the queued constraint in order. This tests CLI buffered input, not a live phone/TUI interaction.
