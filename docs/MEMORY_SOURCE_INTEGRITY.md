# Historical memory source integrity

Alpha's memory graph stores relations such as supersedes and supports graph retrieval. Blue's existing workspace/origin-scoped lexical notes already retain source session IDs, but those pointers did not pin or revalidate captured evidence. This extension improves the existing memory search/save flow rather than creating another graph, tool or automatic execution mechanism.

New references retain native request/result digests alongside session/evidence/message identity. Automatic task recall, `project_memory` search and `/memory` revalidate those references against the current in-memory session or bounded read-only source-session files. Retrieval reports matched historical captures, changed/invalid references, unavailable/oversized sessions, legacy unpinned references and budget exhaustion. Original notes remain historical and untrusted regardless of source matching; note meaning, current code/site, login identity and task completion are never verified by this check.

Bounds per retrieval: four prior source sessions, at most 2 MiB per source file and 4 MiB total file reads, 32 references, 512 KiB per result, 8 KiB per paired request argument and a 4 MiB result revalidation budget. Invalid IDs, symlink/nonregular source files, mismatched session identity/workspace, missing results, digest changes, wrong origin and cached substitutes cannot obtain a matching-source status. Legacy notes deserialize without digest fields but stay unpinned. Source bodies are not copied into the memory report. Native request/result pairing uses the existing audit validator.

Nothing resumes prior sessions, starts a provider, reconnects a browser/MCP server, executes a source file or replays an action. The source-file read is a bounded snapshot; concurrent external modification and whole-memory-plus-session forgery are not prevented by these consistency hashes. The check does not read current project files or fetch current websites, and therefore cannot determine that an otherwise valid old observation remains true today. This is not a semantic memory graph or an Alpha runtime-equivalence claim.

Tests cover persisted capture matching, changed/deleted evidence, old reference compatibility, invalid/traversal IDs, cross-workspace isolation, oversized/symlink source files and source-session budget exhaustion. The actual CLI fixture records a native file observation, saves/searches a note, restarts memory inspection, tampers with and removes its source session, and confirms no extra model requests or source action replay. Physical phone performance and live external providers remain untested.

Independent local review of `f24cff8`/`8caefed` subsequently passed within its inspected scope, including tampering/deletion, duplicate IDs, workspace mismatch and restart without additional requests or private source-body output. The snapshot-only, concurrent-forgery/race and untested-phone limitations above remain unchanged.
