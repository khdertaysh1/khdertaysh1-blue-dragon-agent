# Long user-history projection

The frozen 3e298d5 kept every ordinary user message verbatim at every projection tier. The independent 30-turn Arabic reproduction exhausted local context after 12 turns. Our extended scenario, adding bounded source reads, tool discovery and restart, reproduces exhaustion after 11 completed turns (13 provider requests). These are different scripted workloads, not a live provider capacity measurement.

`reasoning/context.rs::compact_user_repetitions` now applies lossless run encoding to identical adjacent sentence/paragraph patterns in older user messages. Pattern search is bounded to 32 sentence segments. Text, order and repetition counts are retained; each encoded message has its original index and SHA256. Projection uses it only when estimated input falls by at least 25%. Latest two genuine user messages and all system messages stay exact. Session originals, pending tool calls/results and authorization state are unchanged. `recall_context` still returns exact original text; this operation sends no extra provider request and never replays a tool. The mechanical encoding is not a semantic summary, evidence, or new permission.

This intentionally does not silently discard unique instructions or claim to solve arbitrarily large high-information context. Nonrepetitive input that cannot safely fit still produces an honest context blocker. Compression of arbitrary historical prose while preserving every effective constraint remains an open design problem. The 30/30 result applies to this repeated-prose workload, not general hour-long reliability.

AlphaCode code reference: local commit d49f8830dbf1b79f82ad94aee8045c475a3752a6, `alphacode_app_core/agent/compaction.rs::try_auto_compact_after_context_limit` invokes manager `hard_compact_with` with the active model budget and resets provider state. Its compaction core uses importance/constraint scoring and summaries. Blue keeps original storage separate from request projection and chooses lossless encoding for this proven repetition case; no Alpha implementation or credentials were copied. This is a code comparison, not a new runtime Alpha benchmark or claim that this local checkout is the latest remote head.

`scripts/smoke_long_user_projection.py` checks 30 Arabic and 30 English turns, restart after turn 15, full original-user preservation, reconstruction of every encoded request, a 2MB source, exact native window hashes and search offsets, discovery transitions, disconnected browser status, read-only command denial and a bounded no-match search. No-match in 4096 bytes is explicitly incomplete coverage, not proof of absence. The model is scripted and browser checks are status only: approved command execution, a live DOM, service quality and an actual phone require separate qualification. Existing context unit tests preserve pending call pairing, recovery references, recent constraints and fail-closed behavior for oversized unique instructions.

## Nonrepeating counterexample (release blocker)

The added `--distinct` measurement uses 30 distinct messages containing unique numbered observation codes and explicit per-turn restrictions, with the same tools, restart and 32768 context bound. On the frozen 16af304 binary, Arabic messages (first message 4339 characters) completed **6/30** with 7 provider requests; English (5289 characters) completed **13/30** with 15 requests. Both hit local context capacity; all original user messages and source bytes were retained. `acceptance_passed:false` is the result. The script's measurement checks passing does **not** mean session acceptance passed. These are intentionally larger distinct messages than the 1217-character original report, so counts are not a throughput comparison. General high-information history compaction remains unresolved and blocks a broad long-session reliability claim or release acceptance.

## Distinct structured records follow-up

The independent `/tmp/review_unique_users.py` case uses 30 different 1124-character Arabic messages: a distinct protected filename plus twelve distinct path/status records per message. Repetition-only projection still failed after 16 requests. The follow-up `compact_user_records` factors only exact adjacent record structures with different numeric fields. All literal text, every original field string (including leading zeros and Arabic digits), record order, message hash and original index remain available. It does not guess which directives are unimportant or drop observations. The latest two user messages remain verbatim, and all originals remain on disk. This is lossless structure factoring, not model-generated semantic compaction or a claim about arbitrary text entropy.

The unchanged independent reproducer now reaches 30 provider requests with zero local context errors. The bilingual `--structured` scenario additionally verifies each reconstructed record against the original user message across native file tools, discovery and a restart. A separate high-information `--distinct` counterexample remains a required capacity measurement; it must not be relabelled successful based on the structured result. Real model interpretation of the compact representation is not established by a scripted response.
