# Native source consistency across delegates

Alpha's swarm core exposes typed result artifacts and source references to the supervisor. Blue already retains independent child evidence and conflicting model summaries, but did not reconcile whether delegates saw the same source version. This extension adds `source_consistency` to existing status/wait/collect reports, without another tool, child permission, network request or automatic merge.

The existing native `file_outline` result now includes the canonical workspace-relative path alongside its full UTF-8 source hash. The supervisor groups these captures by path, reporting single-agent capture, same captured version, or differing captured versions. Every cited version retains child session/evidence IDs. Runtime captures come from the actual allowlisted tool result; after restart they are rebuilt only from request/result pairs that pass the existing audit validator. Model summaries and peer messages cannot supply capture hashes. Rejected/omitted recovered observations are counted explicitly.

A matching hash means matching captured file content, not semantic agreement, current file state, correct analysis or task completion. Different hashes do not identify which version is newest/correct. No current file is reread, no interrupted action is replayed, and no patch or conclusion is automatically selected/merged. Large-file windows/search hashes are not whole-file captures and are excluded. Older outlines without canonical identity remain unavailable for this comparison; the supervisor does not re-resolve old paths against today's filesystem.

Bounds: existing eight children and 64 considered observations per child, at most 32 reported file groups and 16 cited captures per file, explicit omission counts. Canonical paths stay within the existing grant/workspace boundary; hard-link aliases are not unified. Snapshot hashes are consistency checks, not OS isolation or protection against forging whole child sessions and their evidence digests.

The real CLI fixture starts two independent model/tool loops with explicitly overlapping file grants. It changes the fixture file between native captures while both models return identical summaries, verifies the version mismatch, then tests unchanged captures, restart without child requests, and exclusion/counting of a tampered saved result. Unit tests additionally exclude model-only claims, window hashes, unsafe/legacy identity and verify bounded reporting. No live-provider quality, phone resource behavior or Alpha runtime-equivalence claim follows.
