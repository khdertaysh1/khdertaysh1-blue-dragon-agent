# Local-lab comparison reports

`/audit-report` now includes `local_lab_comparisons`. It connects the approved `run_local_lab` workflow to a bounded historical reproduction record without sending a request or calling a model during export.

Each accepted original run includes its evidence ID and local message reference, strict loopback target, recorded state, attempted request count, typed observations (response status, captured bytes, body/content-type hashes and marker booleans), a canonical three-step recipe, and an outcome recomputed from those observations. Inputs are the application's fixed harmless markers/custom tags, never arbitrary result prose. The fixed preview token is a public synthetic fixture constant, not a session credential. Bodies, arbitrary headers, cookies, model prose and stored verdict text are not copied into the report.

The recipe identifies baseline, changed variant and repeated control, `GET`, query key `q`, the three fixed inputs, request budget, and absence of cookies/redirect following. The report explains the narrow hypothesis: changing the fixed input may change a captured response marker or encoding. It records no browser-execution hypothesis or security finding. A new run requires a new explicit user request, current interact scope, human approval and a fresh ID. Export never repeats the existing run.

The report rechecks native request/result pairing, both digests, normalized requested URL against the strictly validated loopback target, run ID and scenario. Cached/reused status replies do not become additional experiments. It recomputes control consistency and marker/encoding distinctions rather than accepting the recorded verdict. Missing/invalid observation types or hashes are rejected. A completed record requires three ordered observations and an observed execution status. Incomplete captures, unknown outcomes, stopped runs and denied approval remain explicitly inconclusive or not executed. Scope authorization is checked again for reporting, but does not imply live consent or authorize a repeat.

Bounds are the latest 100 observations, twenty runs, 32768 bytes per recorded result and 655360 bytes total scanned result content. Rejected, skipped and older-observation counts remain visible. Only original results still in the session can appear; a durable run journal without its paired tool result is not reconstructed or promoted. Reports are historical and do not revalidate server state or response bodies. File hashes establish consistency, not authenticity against whole-checkpoint rewriting.
