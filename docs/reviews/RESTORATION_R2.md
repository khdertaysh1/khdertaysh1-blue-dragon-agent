# Restoration R2 — rebuilt candidate

This is a new restoration based on R1 commit 5852884a14ffdaecb0237ecc27809b1666537504. It is **not** the missing source for 393ffb0. An earlier uncommitted R2 workspace became unavailable; these changes were reapplied to the verified durable R1 source and independently rebuilt. Only the accompanying final-build test logs apply to this candidate.

## Confirmed implementation changes

* `tool_contract::{validate,normalize}`, `Agent::turn_inner`, `tool_selection::core`: validate native calls with the exact advertised schema; report the offending field path and discovery counts; keep unadvertised errors separate from same-tool correction incidents. A successful native correction resets that tool's incident, while the independent per-turn total remains bounded. `run_command` is core; `write_file` is now core. The user's unknown extra field cannot be identified without their original arguments; local regression uses an explicitly synthetic `cwd` field.
* Command compatibility decodes args JSON **once**, only a bounded array of strings; decimal timeout strings convert only when unambiguous and within 1..300. Broken JSON, nested encodings and program guesses are not repaired. Original provider arguments remain in history; transformations and resulting arguments are recorded separately. Consent is still requested for the resulting command.
* `terminal_input`, `main::chat`, TUI event handling: one CLI event reader, bracketed paste as one input, raw terminal input for long lines, fresh approval events, Enter waits instead of denies. Queued keys are conversation data rather than consent. Cancellation/EOF/channel errors have separate result categories. Command display JSON-escapes newline and quoting. Native dispatch preserves these categories instead of flattening all errors.
* `ToolBox::run_command_with_timeout`: actual stdout/stderr/exit status; spawn failure separate from timeout/cancellation. Unix process-group termination for cancellation/deadline. A timed-out action is unknown and requires inspection, not automatic replay. Explicit rejection blocks later alternative actions in the same turn.
* `reasoning::evidence_memory`, `context::build`: bounded index of digest-verified native historical captures, never assistant prose. Original transcript stays on disk and recall remains available. Historical excerpts are explicitly nonfresh, untrusted and may be truncated. This is not guaranteed semantic memory or proof of the current state. Output reserve matches the request; the Kilo soft input target no longer becomes an invented hard context limit.
* `provider`, `provider_contract`, `streaming`: explicit output budget/source and bounded raw stop reason; no partial or oversized (>8 calls) batch dispatched. Output budget configurable with BLUE_DRAGON_MAX_OUTPUT_TOKENS within client bounds and remaining configured/catalog context. Unknown provider-specific output maxima cannot be guaranteed from incomplete catalog data. Provider truncation is not success; original completed observations are retained for explicit continuation.
* `Agent::turn`, `Coordinator::cooldown_until`: absolute existing cooldown deadline, incoming text retained without extending it or performing actions, one concise notice per deadline. Continue explicitly after waiting; no account/model rotation or automatic command retry.
* `browser`: status is connection status, not page evidence. Unknown mutation blocks further mutations until a fresh valid snapshot; oversized post-dispatch results preserve uncertainty. Read failure is distinct from unknown mutation. Existing compact snapshot URL/title/h1 and literal search behavior retained. Loop counters reset on changed evidence; stable page output does not itself establish task failure or success.
* Empty check collections in ordinary read/download tasks keep the R1 `answer_returned_no_acceptance_contract` result; no claim of comprehensive verification. Code edits can still require actual acceptance checks.

## Validation to accompany the package

Local Linux native tests and Clippy; actual controlling PTY for CLI/TUI including Arabic/English long bracketed paste, original approval, stale queued keys, Enter, refusal, cancellation and EOF. Scripted-provider CLI scenarios cover commands, explicit rejection, file creation/read/calculation/follow-up without tools, local body+headers, literal search/import/export reads, discovery and correction isolation. Provider-boundary fixtures cover synthetic privacy controls and streaming/nonstreaming incomplete reasons. Additional command outcomes and a PTY fixed-429-deadline/no-replay test are included. See BUILD-MANIFEST.json for the exact source tree, hashes and final counts.

These tests use deterministic local providers, not a live model. The mock final calculation reads the actual tool result; it is not a reasoning benchmark. Real Chromium startup was attempted on the local page and blocked by the environment (`socket() Operation not permitted`); no bypass was attempted. JavaScript browser contract tests use mock DOM/APIs. Android ARM64 is cross-compiled, not tested on a physical phone. Windows/macOS were not run here.

Remaining boundaries: bounded excerpts can omit facts, long unique user instructions can still exhaust context, arbitrary natural-language claims are not semantically verified, generic MCP schemas are not a complete JSON Schema implementation, unframed multiline input follows terminal line boundaries, drafts are not guaranteed durable across process death, browser connection liveness still requires IO. No hour-long/live-provider reliability or equivalence to AlphaCode is claimed. Baseline features outside this focused restoration were not re-audited.

## Rebuild

Rust 1.100.0, locked dependencies. Run cargo test --locked --all-targets and cargo clippy --locked --all-targets -- -D warnings. Linux CLI fixtures accept target/debug/blue-dragon. For Android install target aarch64-linux-android and NDK r30; use API26 clang/clang++ and llvm-ar via CC_aarch64_linux_android, CXX_aarch64_linux_android, AR_aarch64_linux_android, CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER. Then cargo build --locked --release --target aarch64-linux-android. No credentials are needed for local scripted acceptance.
